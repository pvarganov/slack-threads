# Slack Threads

Десктопное приложение (Go + Wails) для чтения рабочих Slack-тредов по-русски и ответа
в них по-английски.

Тред добавляется по permalink и сохраняется локально навсегда. При добавлении он целиком
переводится на русский через `claude` CLI, причём весь тред идёт в одну долгоживущую
сессию — терминология не разъезжается между сообщениями. Для треда генерируется блок
«Суть»: о чём обсуждение и что ждут от вас. Ответ пишется по-русски, переводится на
английский, рядом показывается обратный перевод для контроля, и отправляется прямо
в тред.

Что умеет:

- добавление треда по ссылке, локальное хранение в SQLite
- перевод всего треда с сохранением кода, идентификаторов, ссылок и форматирования
- «Обновить» и «Обновить все» — перечитывают тред и переводят только новое
  и изменившееся (сверка по `ts` и хешу текста, поэтому правки старых сообщений тоже
  подхватываются); автоматического поллинга нет
- блок «Суть» треда, пересобирается при непустой дельте
- ответ: RU → EN + обратный перевод, отправка через `chat.postMessage` в тред
- удаление треда (со всеми сообщениями и переводами) и архивация (перестать обновлять,
  перевод сохранить)

## Требования

- macOS (проверялось на darwin/arm64), Go 1.25+ (разрабатывалось на 1.26)
- `claude` CLI 2.1.267 или совместимый — переводчик запускает его подпроцессом
  и работает по подписке, отдельный API-ключ не нужен
- Wails CLI для сборки: `go install github.com/wailsapp/wails/v2/cmd/wails@latest`
- Node.js — для юнит-тестов фронтенда

SQLite подключён через `modernc.org/sqlite` (чистый Go), cgo не требуется.

## Установка

```sh
git clone https://github.com/pavelvarganov/slack-threads.git
cd slack-threads
make test        # go test ./... + тесты фронтенда
make build       # .app в build/bin
```

Прочие цели: `make dev` — запуск с live reload, `make lint` — `golangci-lint`,
`make test-short` — тесты без build/vet-смоука.

## Slack app и scopes

Приложению нужен собственный Slack app с **user-токеном** (`xoxp-`): бот не видит
приватные каналы и личку и не может писать от вашего имени.

1. Создайте app на <https://api.slack.com/apps> → *From scratch*, выберите свой workspace.
2. **OAuth & Permissions** → *User Token Scopes* — добавьте ровно эти:

   | Scope | Зачем |
   |---|---|
   | `channels:history` | читать треды в публичных каналах |
   | `groups:history` | приватные каналы |
   | `im:history` | личные сообщения |
   | `mpim:history` | групповые личные сообщения |
   | `users:read` | имена авторов (`users.info`) |
   | `chat:write` | отправка ответа в тред |

3. *Install to Workspace*. Если самостоятельная установка запрещена политикой
   воркспейса — запрос уйдёт на апрув администратору, придётся подождать.
4. Скопируйте **User OAuth Token** (начинается с `xoxp-`).

## Первый запуск

Запустите приложение и вставьте токен в поле на экране настроек. Токен уходит
в системный keychain (сервис `slack-threads`, аккаунт `slack-user-token`) — в файлах
конфигурации и в базе он не хранится. При старте приложение проверяет токен через
`auth.test` и, если прав не хватает, показывает список нужных scopes.

Дальше: вставьте permalink треда (**Copy link** в меню сообщения в Slack) в поле
добавления. Первый импорт длинного треда небыстрый — Slack отдаёт его страницами
и троттлит; прогресс виден в интерфейсе.

База: `~/Library/Application Support/slack-threads/threads.db`.

### Переменные окружения

Нужны для разработки; в обычной работе всё берётся из значений по умолчанию.

| Переменная | Значение по умолчанию | Что меняет |
|---|---|---|
| `SLACK_THREADS_DB` | `~/Library/Application Support/slack-threads/threads.db` | путь к базе |
| `SLACK_THREADS_TOKEN` | — | токен в обход keychain (тогда он read-only в UI) |
| `SLACK_THREADS_CLAUDE_BIN` | `claude` | путь к бинарнику переводчика |
| `SLACK_THREADS_MODEL` | `opus` | модель перевода |
| `SLACK_THREADS_RESPONSE_TIMEOUT` | `5m` | таймаут одного хода перевода |
| `SLACK_THREADS_IDLE_TIMEOUT` | `15m` | сколько живёт неиспользуемая сессия `claude` |
| `SLACK_THREADS_SLACK_TIMEOUT` | `30s` | таймаут одного HTTP-запроса к Slack |

## Сборка `.app`

```sh
make build          # или: wails build
```

Готовый бандл — `build/bin/slack-threads.app`. Версия проставляется линковкой:
`wails build -ldflags "-X github.com/pavelvarganov/slack-threads/internal/app.Version=1.0.0"`.

Подпись и нотаризация не предусмотрены: приложение личное и запускается локально.
При первом открытии macOS Gatekeeper потребует подтверждения
(Системные настройки → Конфиденциальность и безопасность → *Открыть всё равно*).

## Известные ограничения

- **Нет автоматического обновления.** Треды перечитываются только по кнопке «Обновить»
  или «Обновить все». Поллинга нет сознательно: он быстро упирается в лимиты Slack.
- **Лимиты `conversations.replies`.** Для приложений не из Marketplace метод жёстко
  ограничен (порядка одного запроса в минуту, небольшие страницы). Клиент уважает
  `Retry-After`, делает до 5 повторов и не считает `429` фатальной ошибкой, но первый
  импорт длинного треда может занять минуты. Пагинация ограничена 500 страницами
  (`slackapi.ErrTooManyPages`) — предохранитель от бесконечного курсора.
- **Slack Connect.** В каналы, расшаренные с другой компанией, отправка часто запрещена
  политикой: `chat.postMessage` возвращает `slack_connect…`/`restricted_action…`.
  Приложение показывает понятное сообщение, а переведённый английский текст остаётся
  в черновике — его можно выделить и отправить руками из Slack. Обойти запрет нельзя,
  это правило воркспейса.
- **Только треды.** Отдельное сообщение канала вне треда, файлы, вложения и канвасы
  не импортируются; в переводе остаётся текст сообщения.
- **Удалённые сообщения** остаются локально с пометкой и переводом — история не теряется,
  но и не совпадает один в один со Slack.
- **Перевод зависит от `claude` CLI.** Формы событий `stream-json` не гарантированы
  стабильными между версиями CLI; при обновлении бинарника контракт нужно перепроверять
  (см. ниже). Если бинарника нет или он не исполняемый, приложение говорит об этом прямо.
- **Сессия перевода на диске.** `--resume` требует, чтобы сессии `claude` сохранялись;
  чистка сессий CLI приводит к тому, что тред продолжит переводиться в новой сессии
  (термины прошлой части при этом всё равно передаются в промпте).

## Структура

```
cmd/slack-threads/   точка входа (дубль main.go в корне — его собирает wails)
internal/permalink/  разбор и обратная сборка ссылок Slack
internal/store/      SQLite: схема, миграции, репозитории
internal/slackapi/   HTTP-клиент: conversations.replies, users.info, chat.postMessage
internal/translate/  сессии claude, промпты, перевод, «Суть», черновики ответов
internal/sync/       оркестрация: добавить, обновить один, обновить все
internal/config/     конфиг и токен в keychain
internal/app/        Wails-биндинги
frontend/            HTML/CSS/JS
```

Внешние зависимости (Slack HTTP API, бинарник `claude`) закрыты интерфейсами
и подменяются в тестах: тесты не ходят в сеть и не запускают `claude`.
