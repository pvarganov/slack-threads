# Схема базы данных

Хранилище — SQLite через `modernc.org/sqlite` (чистый Go, без cgo). Файл по умолчанию:
`$(os.UserConfigDir)/slack-threads/threads.db` (на macOS —
`~/Library/Application Support/slack-threads/threads.db`), путь переопределяется
переменной `SLACK_THREADS_DB`.

Схема живёт в `internal/store/migrations.go` — это единственный источник правды;
документ описывает её и обязан обновляться вместе с ней.

## Миграции

Миграции forward-only, применяются по порядку внутри одной транзакции, номер последней
применённой хранится в прагме SQLite `user_version`. Повторное открытие актуальной базы —
no-op. Существующие миграции **не редактируются и не переставляются**, новая всегда
дописывается в конец `migrations`.

| # | Имя | Что делает |
|---|---|---|
| 1 | `initial schema` | все шесть таблиц и индексы |
| 2 | `message deletion flag` | `messages.deleted` |
| 3 | `thread refresh flag` | `threads.needs_refresh` |
| 4 | `thread team id` | `threads.team_id` |

Текущая версия схемы — `store.SchemaVersion` (равна числу миграций).

Соединение открывается с `_pragma=foreign_keys(1)`, `busy_timeout(5000)` и `journal_mode(WAL)`, поэтому каскадные
удаления (`ON DELETE CASCADE`) работают: удаление треда уносит его сообщения, переводы,
суть и черновик.

## Таблицы

### `threads` — тред целиком

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | локальный идентификатор, им оперирует UI и биндинги |
| `channel_id` | TEXT | канал Slack (`C…`, `G…`, `D…`) |
| `thread_ts` | TEXT | `ts` корневого сообщения треда |
| `workspace` | TEXT | поддомен воркспейса из permalink, для обратной сборки ссылок; пусто для ссылок вида `app.slack.com/client/...` |
| `team_id` | TEXT | team ID из ссылки `app.slack.com/client/...`, когда `workspace` пуст — для обратной сборки ссылки в том же виде |
| `title` | TEXT | запасной заголовок: первая строка корневого сообщения как её прислал Slack |
| `title_ru` | TEXT | тема треда по-русски, пишется переводчиком тем же ходом, что и «Суть»; пусто, пока «Суть» ни разу не собиралась |
| `added_at` | INTEGER | unix-время добавления |
| `last_fetched_at` | INTEGER NULL | unix-время последней успешной синхронизации |
| `archived` | INTEGER | 1 — тред больше не обновляется, перевод сохраняется |
| `claude_session_id` | TEXT | id сессии `claude` для `--resume` (см. `claude-cli-contract.md`) |
| `needs_refresh` | INTEGER | 1 — приложение само изменило тред в Slack (отправило ответ), локальная копия отстала; сбрасывается следующей успешной синхронизацией |

Индексы: `UNIQUE (channel_id, thread_ts)` — один тред добавляется один раз, повторное
добавление даёт `store.ErrThreadExists`; `(archived, added_at)` — сортировка списка.

### `messages` — сообщения треда

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | ключ, на который ссылаются переводы |
| `thread_id` | INTEGER FK → `threads.id` | владелец, каскадное удаление |
| `ts` | TEXT | `ts` сообщения, уникален внутри треда |
| `user_id` | TEXT | автор; пусто у сообщений ботов |
| `text` | TEXT | исходный mrkdwn |
| `raw_json` | TEXT | нетронутый payload Slack — позволяет перерисовать сообщение без повторного запроса |
| `edited_ts` | TEXT | `ts` правки, если сообщение редактировали |
| `text_hash` | TEXT | хеш текста; сверка при обновлении ловит правки старых сообщений |
| `deleted` | INTEGER | 1 — сообщение пропало из Slack; локально остаётся вместе с переводом, история не теряется |

Индекс: `UNIQUE (thread_id, ts)` — на нём держится upsert при обновлении.

### `translations` — перевод сообщения на русский

| Колонка | Тип | Смысл |
|---|---|---|
| `message_id` | INTEGER PK, FK → `messages.id` | один перевод на сообщение |
| `text_ru` | TEXT | перевод |
| `model` | TEXT | модель, которой переводили |
| `created_at` | INTEGER | unix-время |

Перевод переписывается только когда изменился `text_hash` исходного сообщения.

### `summaries` — блок «Суть» треда

| Колонка | Тип | Смысл |
|---|---|---|
| `thread_id` | INTEGER PK, FK → `threads.id` | одна суть на тред |
| `text_ru` | TEXT | о чём тред и что ждут от пользователя |
| `based_on_ts` | TEXT | `ts` последнего учтённого сообщения — по нему видно, устарела ли суть |
| `updated_at` | INTEGER | unix-время |

Суть пересобирается только при непустой дельте обновления.

### `users` — кеш профилей Slack

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | TEXT PK | Slack user ID (`U…`, `B…`) |
| `display_name` | TEXT | отображаемое имя |
| `real_name` | TEXT | настоящее имя |
| `is_bot` | INTEGER | 1 — бот или приложение |
| `updated_at` | INTEGER | unix-время записи профиля; сейчас кеш не инвалидируется по возрасту, поле оставлено на будущее |

Кеш экономит вызовы `users.info`: они тоже попадают под лимиты Slack.

### `drafts` — черновик ответа

| Колонка | Тип | Смысл |
|---|---|---|
| `thread_id` | INTEGER PK, FK → `threads.id` | один черновик на тред |
| `text_ru` | TEXT | что пользователь написал по-русски |
| `text_en` | TEXT | перевод на английский — именно он уходит в Slack |
| `back_ru` | TEXT | обратный перевод для самоконтроля |
| `updated_at` | INTEGER | unix-время |

Черновик переживает перезапуск приложения и очищается после успешной отправки.
